# Hecole.Mediator v2.0.0 — Contratos novos, .NET 10 e erros apontados na partida

## PT-BR

### O que é a 2.0

Uma reescrita do Hecole.Mediator com os contratos `IRequest`, `IRequestHandler`, `ISender`, `IPublisher`,
`IMediator`, `IPipelineBehavior` e `INotificationPublisher` no namespace `Hecole.Mediator`. Licença MIT, só .NET 10 e
só dependências da Microsoft
(`Microsoft.Extensions.DependencyInjection.Abstractions` e `Microsoft.Extensions.Logging.Abstractions`).

### O que muda

- **Registro:** `AddHecoleMediator(cfg => ...)` com `RegisterServicesFromAssembly...`,
  `AddOpenBehavior`, `AddBehavior`, `Lifetime` e `NotificationPublisher`. Só os assemblies informados são varridos.
  Registro explícito com `AddRequestHandler` também existe, para quem não quer varredura.
- **Erros de configuração explícitos:** dois handlers para o mesmo pedido lançam no registro, com os dois
  nomes. `VerifyHecoleMediator`, opcional, confere na partida que todo pedido tem handler.
- **Pedido sem resposta**, `Send(object)` e `Publish(object)`.
- **Notifications** um handler por vez por padrão (`ForeachAwaitPublisher`); em paralelo com `TaskWhenAllPublisher`.
- **Behaviors prontos opcionais:** validação por DataAnnotations, log, tempo e exceção. Nenhum entra sozinho e nenhum
  grava o objeto do pedido no log.
- **Analyzer Roslyn no pacote:** pedido sem handler e dois handlers para um pedido (ligadas); regras restritivas que
  cada projeto liga no `.editorconfig` (desligadas).
- **Custo menor por chamada:** na medição publicada em `docs/benchmarks.md` (cronômetro simples, sem ferramenta estatística de benchmark, um
  notebook), `Send` sem behaviors ficou em 79–101 ns e 24 B, contra 1.477–1.967 ns e 768 B da 1.3.0.

### Preciso alterar meu código?

**Sim.** A 2.0 não é compatível com a 1.x: muda o namespace (`Hecole.Mediator`), `ICoreMediator` vira
`IMediator`/`ISender`/`IPublisher`, `AddCoreMediator` sai, behaviors passam a ser registrados explicitamente,
a dependência de validação de terceiros sai e o alvo `net8.0` sai. O passo a passo está no
[guia de migração](../docs/migration-1.x-to-2.0.md). Quem está em .NET 8 continua na 1.3.0.

### Como atualizar

```bash
dotnet add package Hecole.Mediator --version 2.0.0
```

### O que ainda não tem

Pedidos com resposta em fluxo, pre/post processors, exception handlers, handlers genéricos abertos e classe de
mediator pública.
Podem entrar depois sem quebrar a API.

Veja o [CHANGELOG completo](../CHANGELOG.md) e o [README](../README.pt-BR.md).

## EN

### What 2.0 is

A rewrite of Hecole.Mediator with the contracts `IRequest`, `IRequestHandler`, `ISender`, `IPublisher`, `IMediator`,
`IPipelineBehavior` and `INotificationPublisher` in the `Hecole.Mediator` namespace. MIT license, .NET 10 only, and only
Microsoft dependencies
(`Microsoft.Extensions.DependencyInjection.Abstractions` and `Microsoft.Extensions.Logging.Abstractions`).

### What changes

- **Registration:** `AddHecoleMediator(cfg => ...)` with `RegisterServicesFromAssembly...`,
  `AddOpenBehavior`, `AddBehavior`, `Lifetime` and `NotificationPublisher`. Only the assemblies you name are scanned.
  Explicit registration with `AddRequestHandler` is also available, for projects that do not want scanning.
- **Explicit configuration errors:** two handlers for the same request throw at registration, with both
  names. The optional `VerifyHecoleMediator` checks at start-up that every request has a handler.
- **Requests without a response**, `Send(object)` and `Publish(object)`.
- **Notifications** run one handler at a time by default (`ForeachAwaitPublisher`); in parallel with
  `TaskWhenAllPublisher`.
- **Optional built-in behaviors:** DataAnnotations validation, logging, timing and exceptions. None is registered by
  default and none writes the request object to the log.
- **Roslyn analyzer in the package:** request without handler and two handlers for one request (on); restrictive rules
  that each project turns on in `.editorconfig` (off).
- **Lower cost per call:** in the measurement published in `docs/benchmarks.md` (plain stopwatch, not a statistical benchmark harness, one
  laptop), `Send` with no behaviors took 79–101 ns and 24 B, against 1,477–1,967 ns and 768 B in 1.3.0.

### Do I need to change my code?

**Yes.** 2.0 is not compatible with 1.x: the namespace changes (`Hecole.Mediator`), `ICoreMediator` becomes
`IMediator`/`ISender`/`IPublisher`, `AddCoreMediator` is removed, behaviors are registered explicitly, the third-party validation dependency
is removed and the `net8.0` target is removed. The step-by-step guide is in the
[migration guide](../docs/migration-1.x-to-2.0.md). Projects on .NET 8 stay on 1.3.0.

### How to update

```bash
dotnet add package Hecole.Mediator --version 2.0.0
```

### Not available yet

Streaming requests, pre/post processors, exception handlers, open generic handlers and a public mediator class. They may
be added later without breaking the API.

See the [full CHANGELOG](../CHANGELOG.md) and the [README](../README.md).
